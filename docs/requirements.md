# 転倒・フレイル予防アプリ 要件メモ

2026年11月13日作成

高齢者が自宅で一人で行う転倒予防運動アプリを、Claude Codeで作るための要件メモです。このファイルの内容に沿って、フェーズ1から順に実装します。

## 目的と使う人

転倒予防のための筋力・バランス運動を、高齢者が自宅で一人で、安全に続けられるようにするアプリです。

| 役割 | 何をするか | 使う画面 |
| --- | --- | --- |
| 本人（高齢者） | メニューを読み込み、アニメを見ながら運動し、記録する | 本人用の画面 |
| 医師 | 受診時にレベル・回数・強度の上限を決めてメニューを渡し、記録を一緒に振り返る | メニュー作成画面、振り返り画面 |

- 最初の利用者は開発者の家族で、不特定多数への公開は当面しません。
- 端末はスマホかタブレットで、縦向きを基本にします。
- 運動は週3回以上、約30分の標準セッションと約10分の短いセッションで行います。

## やらないこと

次の機能は作りません。安全を保ち、医療機器に当たらない設計にとどめるための制約です。

- サーバー、アカウント、ログインは作りません。記録は端末内だけに保存します。
- 利用データを外部に送りません。解析ツールや広告も入れません。
- レベル・支えの段階・回数を、アプリが自動で変えることはしません。変更は、医師が渡す新しいメニューを読み込んだときだけ起こります。
- 転倒リスクや体の状態を、アプリが評価・判定・診断することはしません。バランスの姿勢は練習として表示し、合否や点数は出しません。
- カメラやセンサーで動きを測ったり、フォームを判定したりしません。カメラはメニューのQRを読むためだけに使います。
- 病気の治療や予防の効果をうたう表現は使いません。体調が悪いときの案内は「医療機関に相談する」という一般的な表現にとどめます。
- 他者の動画・画像・説明文は使いません。人物の絵、説明文、音声はすべて独自に作ります。

## 技術構成

サーバーを持たない静的なPWAとして作り、iPhoneのホーム画面から起動する使い方を最優先にします。

| 項目 | 採用 | 補足 |
| --- | --- | --- |
| 言語・ビルド | TypeScript（strict）、Vite | |
| UI | React | ルーターは入れず、画面は状態で切り替える |
| アニメ | Canvas 2D と自前のキーフレーム補間 | 外部のアニメ用ライブラリは使わない |
| 保存 | IndexedDB（薄いラッパー経由） | メニュー、記録、設定を保存する |
| オフライン | Service Workerで全ファイルをキャッシュ | 初回の読み込み後は通信なしで動く |
| QR | 生成・読み取りとも小さなライブラリを使う | Safariが標準のバーコード読み取りAPIに対応していないため |
| 音声 | 端末の読み上げ機能（Web Speech API） | 実機で聞き、不十分なら録音音声に差し替えられる構造にする |
| 画面の消灯防止 | Screen Wake Lock API | 使えない端末でもエラーにせず続行する |
| テスト | Vitest | データの検証と補間計算の単体テスト |
| 配置 | HTTPSの静的ホスティング | サービスは未決 |

### iPhoneで動かすときの注意

- ホーム画面に追加したアプリは、Safariとは別の保存領域を持ちます。Safariのまま使うと、7日間使わなかったときに保存データが消えることがあります。初回に「ホーム画面に追加」を案内し、ホーム画面から起動していないときは案内を出します（[web.dev](https://web.dev/articles/storage-for-the-web)）。
- iPhoneの標準カメラでQRを読むと、通常はSafari側で開くため、ホーム画面のアプリには届きません。メニューの読み込みは必ずアプリの中で行います。
- 画面の消灯防止は、ホーム画面のアプリではiOS 18.4以降で動きます（[Safari 18.4 リリースノート](https://developer.apple.com/documentation/safari-release-notes/safari-18_4-release-notes.md)）。

## 画面と流れ

本人が触る画面は5つに絞り、運動中は操作なしで進むようにします。医師が使う画面は、暗証番号の奥に置きます。

| 画面 | 使う人 | 主な内容 |
| --- | --- | --- |
| はじめに（初回のみ） | 本人 | ホーム画面への追加の案内、メニュー未設定のときの案内 |
| ホーム | 本人 | 「今日の運動を始める」「短い運動をする」「歩いた」の3つのボタン、今週の実施状況 |
| 開始前チェック | 本人 | 体調・靴・床・支持物・電話の確認、「今日は休む」 |
| 運動の再生 | 本人 | アニメ、運動名、回数や秒数のカウント、注意点を1つ、音声、一時停止と中止 |
| 終了 | 本人 | きつさの記録、転倒・ヒヤリの有無 |
| 振り返り | 本人と医師 | 実施した日、週ごとの回数、きつさの推移、転倒・ヒヤリの記録、現在のメニュー |
| 医師用設定 | 医師 | メニューの作成と変更、QRと印刷シートの作成、メニューの読み込み |

### 1回の運動の流れ

1. ホームで「今日の運動を始める」を押す。
2. 開始前チェックに答える。「今日は休む」を選ぶと、休んだ日として記録して終わる。
3. 運動ごとに、立位の種目なら支持物の確認を出し、アニメと音声で実施する。
4. 種目の間は短い休憩をはさみ、カウントダウンのあと自動で次へ進む。
5. 最後にきつさと、転倒・ヒヤリの有無を記録して、ホームに戻る。

### メニューを端末に入れる方法

| 方法 | 使う場面 | 作るフェーズ |
| --- | --- | --- |
| 医師用設定の画面で直接設定する | 対面で会うとき（基本の方法） | 1 |
| アプリ内でQRを読み取る | 印刷したシートを渡す、郵送する | 4 |
| メニューコード（文字列）を貼り付ける | QRが読めないときの予備 | 4 |

## 安全機能

次の11項目は省略できない要件です。実装やテストでは、この番号で参照します。

| 番号 | 要件 |
| --- | --- |
| S-1 | メニューが未設定のときは、運動を始められない。 |
| S-2 | 開始前チェックで体調（発熱、痛み、めまい、胸の症状）をたずね、当てはまるものがあればその日は始めず、休みとして記録する。 |
| S-3 | 開始前チェックで、滑りにくい靴、床に物がないこと、支持物の位置、電話が手の届く所にあることを確認し、整ってから進む。 |
| S-4 | 「今日は休む」をいつでも選べる。休んだ日を責める表現は使わない。 |
| S-5 | 強度の上限（医師がメニューで設定）と中止の目安を、セッションの最初に毎回表示する。中止の目安は、胸の痛み、いつもと違う息切れ、めまい、動悸、関節の痛み。 |
| S-6 | 立位の種目の前に、動かない椅子の背かカウンターがすぐ横にあるかを確かめる画面を出す。 |
| S-7 | 運動中は「中止」ボタンを常に表示する。中止したら理由を1回のタップで選べるようにし（痛み、息切れやめまい、疲れ、その他）、症状があるときは医療機関に相談するよう一般的な文言で案内する。 |
| S-8 | レベル・支えの段階・回数・秒数は、メニューにある値だけを使う。アプリが増やしたり、次のレベルを提案したりしない。 |
| S-9 | メニューにない種目は表示しない。高リスクの種目は、メニューで明示的に選ばれたときだけ表示する。 |
| S-10 | アニメでは支持物を常に描き、人物はメニューの支えの段階どおりにつかまる。 |
| S-11 | 転倒・ヒヤリを記録したとき、またはメニューの設定から見直し日数（初期値90日）が過ぎたときは、医師に相談する時期であることを知らせる。運動は止めない。 |

## データ定義

扱うデータは、アプリに同梱する「運動」、医師が決める「メニュー」、端末内に残す「記録」の3種類です。型は次を出発点にし、実装で必要になった項目は足して構いません。

```typescript
type Level = 1 | 2 | 3;
type SupportStage = 'both' | 'one' | 'fingertip' | 'none'; // 両手・片手・指先・なし
type View = 'front' | 'side' | 'back';

// 運動（アプリに同梱。利用者のデータではない）
interface Exercise {
  id: string;                 // 例 'S1'
  name: string;               // 表示名
  category: 'warmup' | 'strength' | 'balance' | 'dynamic' | 'walking';
  highRisk: boolean;          // true の種目はメニューで明示的に選んだときだけ表示
  unit: 'reps' | 'seconds' | 'laps' | 'minutes';
  bilateral: boolean;         // 左右を入れ替えて行うか
  cues: string[];             // 注意点。1つ目を画面に大きく出す
  variants: ExerciseVariant[];
}

interface ExerciseVariant {
  level: Level;
  howTo: string;              // そのレベルでの行い方（短い文）
  usesSupport: boolean;       // 支持物を使うか
  view: View;                 // 主な視点
  animationId: string | null; // キーフレームの参照。未作成なら null
}

// メニュー（医師が決める。QRやコードに入るのはこれだけ）
interface Menu {
  v: 1;                       // 形式の版
  issuedOn: string;           // 'YYYY-MM-DD'
  reviewAfterDays: number;    // 見直し日数。初期値 90
  support: SupportStage;      // 立位種目の支えの段階
  intensityCap: string;       // 強度の上限の文言
  standard: MenuItem[];       // 標準セッション
  short: MenuItem[];          // 短いセッション
  walking?: { minutes: number; daysPerWeek: number };
}

interface MenuItem {
  ex: string;                 // 運動ID
  level: Level;
  amount: number;             // 回数・秒数・往復数
  sets: number;
}

// 記録（端末内だけに保存）
interface SessionRecord {
  id: string;
  date: string;               // 'YYYY-MM-DD'
  kind: 'standard' | 'short' | 'rest' | 'walk';
  completed: string[];        // 終えた運動ID
  stopped?: { ex: string; reason: 'pain' | 'breath-dizzy' | 'tired' | 'other' };
  exertion?: 1 | 2 | 3 | 4 | 5; // きつさ。1 とても楽 〜 5 とてもきつい
  fall: boolean;
  nearMiss: boolean;
  walkMinutes?: number;
}
```

### メニューの決まり

- メニューには、氏名や生年月日など個人を特定する情報を入れません。
- メニューコードは `FPM1:` に続けて、メニューのJSONをbase64urlにした文字列とします。QRにはこの文字列をそのまま入れ、URLにはしません。
- 読み込み時に必ず検証します。知らない版、知らない運動ID、その運動にないレベル、範囲外の値があれば、全体を拒否して元のメニューを残します。
- 値の範囲（暫定）は、回数1〜20、秒数5〜60、往復1〜10、セット1〜3、見直し日数30〜180です。
- 新しいメニューを読み込む前に、現在との違いを一覧で見せ、医師が確認してから置き換えます。

## アニメーション

運動の見本は、Canvasに描く2Dの人物を関節角度のキーフレームで動かして作ります。動画や画像からのなぞり書きはせず、動きの形は運動データの注意点と、付録の「動きの仕様」から定義します。どちらを読んでも動きの形が一つに決まらない種目は、作る前に質問します。

### 人物モデル

- 頭、体幹、骨盤、上腕、前腕、大腿、下腿、足を節とする関節モデルにします。視点（正面・横・後ろ）ごとに2Dで定義し、3Dにはしません。
- 棒人間ではなく、太さのある手足と人に近い体型で描きます。顔の細部は不要です。背景は無地にします。
- 床についている足は動かさず、その足を起点に体の位置を計算します。足が滑って見えないようにするためです。
- つかまる手は、支持物の位置に腕の2関節を合わせます。支えの段階（両手・片手・指先・なし）は腕だけを切り替え、下半身のキーフレームは共通にします。
- 左右を入れ替える種目は、同じキーフレームを左右反転して使います。

### キーフレームのデータ

- 1つのアニメは、視点、1往復の時間、キーフレームの列（時刻と各関節の角度）、支持物の種類と位置、手の接触、字幕の区間で構成します。JSONで持ち、コードと分けます。
- キーフレームの間は、ゆっくり始まりゆっくり止まる補間でつなぎます。上げ下げはそれぞれ2〜3秒を基準にします。
- 1往復の終わりを回数のカウントと音声に合わせます。秒数で行う種目は、姿勢を保ったまま残り秒数を表示します。

### 見せ方

- 動かしている部位を目立つ色にし、椅子やカウンターは落ち着いた色で常に描きます。
- 注意点は、矢印や水平線などの印を体の上に重ねて示します（例：骨盤を水平に保つ線）。
- スマホの縦画面で、人物の全身と足元が切れずに入る大きさにします。

### プレビュー画面（開発用）

- アニメの一覧、コマ送り、各関節の角度を変えるスライダー、JSONの書き出しを備えた開発用の画面を作ります。本番の画面からは入れないようにします。
- 体の各節の質量比から重心を計算し、重心の真下の点と、足と支持物で支える範囲を重ねて表示します。重心が範囲の外に出るコマには警告を出します。質量比の値と出典は、データファイルにコメントで残します。
- 最初に作るのは、S1「椅子からの立ち座り」の横向き（レベル1と2）です。ここで画風と作り方を固めてから、ほかの種目に進みます。

## 見やすさと操作

高齢者が一人で迷わず使えることを基準にし、運動中は画面に触れなくても進むようにします。

| 項目 | 基準 |
| --- | --- |
| 文字 | 本文は18px相当以上、ボタンと見出しは22px相当以上、運動中の回数・秒数は48px相当以上。端末の文字サイズ設定に従って大きくなる |

## 付録：アニメ確認チェックリスト

運動リストの文書にあるチェックリストを転記したものです。フェーズ2以降、各アニメはこの項目で仕様と照合します。

### A. 仕様との照合

- [ ] 開始姿勢が仕様どおり（足の位置と幅、手の支え、背筋）
- [ ] 動きの方向と大きさが仕様どおり
- [ ] 終了姿勢と戻り方が仕様どおり
- [ ] 反動がなく、上げ下げとも一定の速さでゆっくり動く
- [ ] 回数・秒数の表示がメニューと一致する

### B. 力学的な妥当性

- [ ] 重心が常に支える面（足と支持物）の上にある
- [ ] 支えている足が滑らず、浮かない
- [ ] 関節が可動域を超えず、不自然なねじれがない
- [ ] 左右を入れ替える種目で、動きが左右対称
- [ ] つかまる表現では、手が支持物に実際に触れている

### C. 安全の表現

- [ ] 支持物（椅子の背・カウンター）が常に画面内にある
- [ ] 支えの段階（両手・片手・指先・なし）がレベルと一致する
- [ ] 高リスク種目では、人物が支持物のすぐ横に立っている

### D. 注意点の伝わり方

- [ ] 主な注意点が、矢印や強調表示で動きと同時に示される
- [ ] 音声と字幕の説明が、アニメの動きと合っている
- [ ] よくある誤り（例：体を傾けて脚を上げる）を示す必要があるか検討した

### E. 見やすさ

- [ ] スマホの縦画面でも、人物の全身と足元が十分な大きさで見える
- [ ] 背景は無地で、文字は大きい

## 付録：動きの仕様

名前と注意点だけでは動きの形が一つに決まらない種目について、形を定めます。

### W1 足首回し

- レベル1：椅子に座り、片足を少し前に出して、かかとを床につけたまま、つま先で円を描く。
- レベル2：支持物につかまって立ち、体重を反対の足に乗せて、同じようにつま先で円を描く。
- 外回し5回、内回し5回のあと、足を替える。1周を1回と数える。

### W2 腕回し

- どのレベルでも椅子に座って行う。
- 指先を肩に置き、両肘で同時に大きな円を描く（前→上→後ろ→下）。
- 後ろ回し5回、前回し5回。肩がつらいときは円を小さくする。

### W3 腕を上げて体をひねる

- どのレベルでも椅子に座って行う。
- 両腕を肩の高さで前に伸ばし、手のひらを合わせる。
- 骨盤と足は正面のまま、胸と腕を一緒に右へ45度程度までひねって戻し、次に左へひねる。片側1回ずつ数える。

### S8 肩甲骨寄せ

- 背筋を伸ばし、バンドを胸の前で肩幅に持つ。
- 肘を伸ばしたまま左右に引き広げ、肩甲骨を寄せて2〜3秒止め、ゆっくり戻す。
- バンドがないときは、肘を90度に曲げて脇につけ、肘を後ろに引いて肩甲骨を寄せる。
- 後ろから見て、肩が上がらないことが分かるように描く。
